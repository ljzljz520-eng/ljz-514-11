# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, region?, openTime?, stayMinutes?, desc? }, ...]`
- 说明：`lat` / `lng` 可能为 `null`（坐标缺失的景点仍返回，供后台维护；不参与路径计算）

### 2.3 最短路径
- `GET /api/path?from=<id>&to=<id>`
- 成功返回：
  - `startId` / `endId`
  - `totalDistanceMeters`
  - `pathNodeIds` / `pathNodes`
  - `segmentDistanceMeters`
- 失败返回：`{ error: "...中文错误信息..." }`
- 约束：起点或终点坐标缺失时返回 400，提示"缺少坐标，无法参与路径计算"

### 2.4 景点节点维护（后台）
- `POST /api/admin/nodes`：新增景点
  - 请求体 JSON：`{ id?, name, lat?, lng?, region?, openTime?, stayMinutes?, type?, desc? }`
  - `name` 必填；`id` 缺省时自动生成；`lat`/`lng` 需同时填写或同时留空
  - 保存成功后立即重建图，新节点（有坐标时）即刻参与路径计算
- `PUT /api/admin/nodes?id=<id>`：更新景点（仅覆盖请求中出现的字段，可用于补录坐标）
- 校验失败返回 400 与中文错误信息（名称缺失、经纬度不成对、经纬度越界、停留时长非正整数等）

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索），选项来自节点列表；坐标缺失的景点置灰不可选
- 交换起终点、清空选择
- 一键规划并展示总距离与路径节点列表（含所属区域、开放时间、推荐停留时长）

### 3.2 地图交互
- 渲染所有有坐标的景点 Marker（缺坐标景点不上图）
- Marker Popup 支持“一键设为起点/终点”
- 规划成功后绘制路线 Polyline

### 3.3 节点管理页（`/admin`）
- 表格展示全部景点：名称、所属区域、经纬度、开放时间、推荐停留时长、是否可参与路径计算
- 新增/编辑弹窗维护景点信息；坐标可暂缺，后续补录后即参与路径计算

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name,lat,lng`（其他列可选：`type`、`region`、`open_time`、`stay_minutes`、`desc`）
- `edges.csv`：可选；至少包含 `from,to`；权重列支持：`distance_meters` / `weight_meters` / `distanceMeters` / `weightMeters`

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示
- 后端：构图仅使用坐标完整的节点；坐标缺失的节点不参与邻接与最短路计算
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 为边增加更多权重维度（拥堵、票价、偏好等）
