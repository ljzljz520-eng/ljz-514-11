# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, desc?, region?, openingHours?, recommendedStayMinutes? }, ...]`
- 说明：`lat` / `lng` 可能为 `null`，表示坐标缺失；坐标缺失节点仍会返回（供后台维护），但不参与路径计算

### 2.3 最短路径
- `GET /api/path?from=<id>&to=<id>`
- 成功返回：
  - `startId` / `endId`
  - `totalDistanceMeters`
  - `pathNodeIds` / `pathNodes`
  - `segmentDistanceMeters`
- 失败返回：`{ error: "...中文错误信息..." }`
- 起点或终点坐标缺失时返回 400：`起点或终点缺少坐标，无法参与路径计算`

### 2.4 景点节点维护
- `POST /api/nodes`：新增景点。请求体字段：
  - `name`（必填）、`id`（可选，缺省自动生成 `N_xxx`）
  - `lat` / `lng`（可选，经纬度必须同时填写或同时留空，范围分别为 ±90 / ±180）
  - `region`（所属区域）、`openingHours`（开放时间，自由文本）、`recommendedStayMinutes`（推荐停留时长，分钟，正整数）
  - `type` / `desc`（原有可选字段）
  - 成功返回 201 与新建节点
- `PUT /api/nodes/{id}`：更新景点（字段同上，`name` 非空时更新；传入 `lat/lng` 为 null 可清空坐标）
  - 节点不存在返回 404
- `DELETE /api/nodes/{id}`：删除景点，成功返回 `{ id, deleted: true }`，不存在返回 404
- 任意写操作成功后，后端从数据库重新加载节点并重建图，使后续路径计算立即生效

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索），**仅列出坐标完整的景点**；坐标缺失景点不出现在候选中
- 交换起终点、清空选择
- 顶部“景点节点维护”入口（抽屉式后台）：新增 / 编辑 / 删除景点，维护名称、经纬度、所属区域、开放时间、推荐停留时长
- 一键规划并展示总距离与路径节点列表（含区域、开放时间、建议停留）

### 3.2 地图交互
- 仅渲染坐标完整的景点 Marker（坐标缺失节点无坐标，无法定位）
- Marker Popup 支持“一键设为起点/终点”，并展示区域、开放时间、建议停留
- 规划成功后绘制路线 Polyline

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name`（其他列可选）
- `lat` / `lng` 可同时缺省（坐标缺失节点可被维护展示，但不参与路径计算）；只填一个会跳过该行
- 可选列：`type`、`desc`、`region`、`opening_hours`（或 `openingHours`）、`recommended_stay_minutes`（或 `recommendedStayMinutes`）
- `edges.csv`：可选；至少包含 `from,to`；权重列支持：`distance_meters` / `weight_meters` / `distanceMeters` / `weightMeters`

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示；新增/更新接口对名称、经纬度成对性、范围与停留时长做校验
- 升级旧库时启动迁移会自动放宽历史 `nodes.lat/lng` 的 NOT NULL 约束，以支持坐标缺失
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃；坐标缺失节点在起终点选择中禁用
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 为边增加更多权重维度（拥堵、票价、偏好等）
