# 测试报告（中文）

## 1. 测试范围
- Docker 一键启动（前端/后端/数据库）
- 后端接口：健康检查、节点列表、最短路径、景点节点增删改
- 前端页面：加载节点、景点维护、起终点选择（坐标缺失过滤）、地图渲染与路径展示
- 数据文件：`nodes.csv` 导入（含坐标缺失行）、`edges.csv` 读取与优先级

## 2. 自测环境
- macOS + Docker Desktop
- 前端：Nginx 静态站点（容器）
- 后端：Java 17（容器）
- 数据库：PostgreSQL 15（容器）

## 3. 自测用例与结果

### 3.1 服务可用性
- 访问前端首页：`http://localhost:3514/`（通过）
- 健康检查：`GET http://localhost:8514/api/health`（通过）

### 3.2 节点数据
- `GET /api/nodes` 返回节点数组且包含 `id/name/lat/lng` 及 `region/openingHours/recommendedStayMinutes`（通过）
- 坐标缺失节点 `lat/lng` 为 null 时仍在列表中返回（通过）

### 3.3 路径规划
- 正常参数：`GET /api/path?from=JIEFANGBEI&to=HONGYADONG` 返回路径与距离（通过）
- 非法节点：`GET /api/path?from=NOPE&to=HONGYADONG` 返回 400 且中文错误（通过）
- 起点或终点坐标缺失：返回 400「起点或终点缺少坐标，无法参与路径计算」（通过，单元测试 `nodesWithoutCoordinatesCannotParticipateInPath`）

### 3.4 景点节点维护
- `POST /api/nodes` 新增带完整字段的景点，返回 201；未传 `id` 时自动生成 `N_xxx`（通过）
- 仅填一个经纬度 / 经纬度越界 / 名称为空 / 停留时长非正，均返回 400 中文提示（通过）
- 坐标缺失景点可新增并在 `GET /api/nodes` 中返回；`PUT` 补全坐标后即可参与规划（通过）
- `DELETE /api/nodes/{id}` 成功返回 deleted=true，重复删除返回 404（通过）
- 写操作后图自动重建，新节点立即可以参与路径计算（通过）

### 3.5 edges.csv 优先级
- 当 `edges.csv` 存在且包含 `from,to` 时，构图优先使用边数据；缺失权重则按经纬度计算（通过）
- 当 `edges.csv` 缺失或为空时，自动生成边并保证尽可能连通（通过）

### 3.6 前端
- `tsc -b --noEmit` 类型检查通过；`vite build` 生产构建通过；`eslint .` 无错误（通过）
- 起点/终点下拉仅显示坐标完整景点，坐标缺失数量有提示；地图仅渲染坐标完整 Marker（通过）

## 4. 已知限制
- 地图瓦片依赖 OpenStreetMap 外部网络；在无外网环境下瓦片可能加载失败，但不影响接口与规划逻辑
- `pnpm` 版本更新提示属于正常提示信息，不影响构建；建议保持 lockfile 与 `package.json` 同步
