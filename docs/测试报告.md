# 测试报告（中文）

## 1. 测试范围
- Docker 一键启动（前端/后端/数据库）
- 前端页面：加载节点、选择起终点、地图渲染与路径展示
- 后端接口：健康检查、节点列表、最短路径
- 景点节点维护：新增/编辑/删除、入参校验、图自动重建
- 坐标约束：坐标缺失的景点不参与路径计算（前端禁用 + 后端拒绝）
- 数据文件：`nodes.csv` 导入、`edges.csv` 读取与优先级

## 2. 自测环境
- macOS + Docker Desktop
- 前端：Nginx 静态站点（容器）
- 后端：Java 17（容器）
- 数据库：PostgreSQL 15（容器）

## 3. 自测用例与结果

### 3.1 服务可用性
- 访问前端首页：`http://localhost:3514/`（通过）
- 健康检查：`GET http://localhost:8514/api/health`（通过）

### 3.2 节点数据
- `GET /api/nodes` 返回节点数组且包含 `id/name/lat/lng`（通过）

### 3.3 路径规划
- 正常参数：`GET /api/path?from=JIEFANGBEI&to=HONGYADONG` 返回路径与距离（通过）
- 非法节点：`GET /api/path?from=NOPE&to=HONGYADONG` 返回 400 且中文错误（通过）

### 3.4 edges.csv 优先级
- 当 `edges.csv` 存在且包含 `from,to` 时，构图优先使用边数据；缺失权重则按经纬度计算（通过）
- 当 `edges.csv` 缺失或为空时，自动生成边并保证尽可能连通（通过）

### 3.5 景点节点维护（后台）
- `POST /api/admin/nodes` 新增景点（含区域/开放时间/停留时长），返回 201 且节点列表可见（通过）
- `PUT /api/admin/nodes/{id}` 更新景点信息，返回 200（通过）
- `DELETE /api/admin/nodes/{id}` 删除景点，返回 200；删除后该节点不可再作为起终点（通过）
- 写操作后图自动重建：新增带坐标景点后可立即参与路径规划（通过）
- 入参校验：缺名称、经纬度不成对、经纬度越界、停留时长为负均返回 400 中文错误（通过）
- 重复 ID 新增返回 409；更新/删除不存在的 ID 返回 404（通过）

### 3.6 坐标缺失约束
- 新增无坐标景点成功，但不进图：`GET /api/path` 以其为起终点返回 400「缺少坐标」（通过）
- 前端起终点下拉中该景点禁用且标注“缺坐标”；地图上不渲染其标注（通过）
- 补全坐标（PUT）后可正常参与路径规划（通过）
- 单元测试：`GraphServiceTest`（缺坐标节点不进图、edges 中引用缺坐标节点被忽略）与 `NodeValidatorTest`（7 例）全部通过

## 4. 已知限制
- 地图瓦片依赖 OpenStreetMap 外部网络；在无外网环境下瓦片可能加载失败，但不影响接口与规划逻辑
- `pnpm` 版本更新提示属于正常提示信息，不影响构建；建议保持 lockfile 与 `package.json` 同步
